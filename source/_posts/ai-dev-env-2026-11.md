## 道具

### Claude Code

- 開発のほぼすべてをこれでやる
- Claude デスクトップアプリの Code タブで使う。ターミナル版はほぼ使わない
- モデルは Fable 5（1M コンテキスト）を既定にしている
- プラン: TODO

### Codex CLI

- 設計してから書き起こす大きめの実装と、コードレビューに使う
- Claude Code のサブエージェントから `codex exec` で呼ぶ。直接はあまり触らない
- モデルは gpt-6-astra、reasoning effort は medium

### その他

- ブラウザ: アプリ内蔵のブラウザで画面を確かめる
- Word・Excel: computer use で裏で操作する
- MCP: Slack や Linear などをつなぐ

## 設定の置き場所

設定は claude-shared という GitHub のリポジトリにまとめ、`setup.sh` で `~/.claude` にシンボリックリンクを張る。どのマシンでも同じ設定になる。

```
claude-shared/
├── setup.sh             # ~/.claude へリンクを張る
├── CLAUDE.md            # 全プロジェクト共通のルール
├── agents/              # サブエージェント（8個）
├── skills/              # スキル（12個）
├── hooks/               # フックのスクリプト
└── settings.local.json  # 権限・モデルなど。~/.claude/settings.json にマージする
```

- エージェントとスキルは1つずつリンクする。リポジトリに入れたくない自作のものと共存させるため
- `settings.json` はマシン固有の設定も入るので、リンクではなくマージにしている
- 設定を変えるときも、ブランチを切って PR にする

### CLAUDE.md

指摘したことを、日付と理由を付けてルールとして足していく。今あるルールの例:

- PR は1つの依頼につき1つ
- マージは自分が指示したときだけ
- 「動いた」は、ログではなく画面や届いたもので確かめてから言う
- プロセスを上限なしで並列起動しない（742本立ち上げて Mac が固まった）
- 人が読む文字は少なく短く

### スキル

よく使うもの:

- `dev`: 設計 → 実装 → レビュー → PR 作成まで
- `review_and_fix`: レビュアーを回して指摘を直す
- `pr-body`: PR 本文の見出しと書き方
- `slack-post`: Slack に投稿する文の書き方
- `ui-design`: 画面を作る前に案を出す
- `wait`: レビューや CI を1時間ごとに確かめる

### サブエージェント

- Codex 系: 実装役、コードレビュー、設計レビュー、要件の穴出し
- Claude 系: コードレビュー、設計レビュー、読みやすさのレビュー、デザインシステムへの準拠チェック

### 権限とフック

- 権限は auto モード。よく使うコマンドは許可リスト、消す操作などは ask リストに入れる
- フックは日本語で答えさせるものだけ

## 開発の流れ

1. チャットで依頼する（Issue があれば URL を渡す）
2. `dev` スキルで設計・実装
3. レビュアーのサブエージェントを回して直す
4. PR の URL が返ってくる
5. 自分で見て「マージして」と指示する

## 小ネタ

- 数行の直しは Claude が自分で書く。Codex に頼むと1件4〜6分かかっていた
- テストとレビューは push の前に1回だけ回す
- 確認用の開発サーバーは `nohup` で切り離して起動する。アプリと一緒に落ちないように
- Word・Excel は `open -g` で裏で開く。作業中の画面の前に出てこないように

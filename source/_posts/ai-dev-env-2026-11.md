### 使っているやつ

- Claude Code
  開発はほぼ全部これ
  Claude のデスクトップアプリの Code タブで使ってる。ターミナル版はほぼ使わない
  - プラン：Ultra
  - モデル：Fable 5（1M コンテキスト）
- Codex CLI
  大きめの実装とコードレビューをやらせるやつ
  Claude Code のサブエージェントから `codex exec` で呼んでるので、直接はあんまり触らない
  - モデル：gpt-6-astra（reasoning effort は medium）
- アプリ内蔵のブラウザ
  作った画面を Claude に確かめさせるやつ
- computer use
  Word や Excel を裏で操作させるやつ
- MCP
  Slack とか Linear とかをつなぐやつ

### 設定の置き場所

設定は claude-shared という GitHub のリポジトリにまとめてます
`setup.sh` で `~/.claude` にシンボリックリンクを張るので、どの Mac でも同じ設定になる

```
claude-shared/
├── setup.sh             # ~/.claude へリンクを張る
├── CLAUDE.md            # 全プロジェクト共通のルール
├── agents/              # サブエージェント（8個）
├── skills/              # スキル（12個）
├── hooks/               # フックのスクリプト
└── settings.local.json  # 権限・モデルなど。~/.claude/settings.json にマージする
```

- エージェントとスキルは1つずつリンクする
  リポジトリに入れたくない自作のやつと共存させるため
- `settings.json` はマシン固有の設定も入るので、リンクじゃなくてマージにしてる
- 設定を変えるときもブランチを切って PR にしてる

#### CLAUDE.md

Claude に指摘したことを、日付と理由付きでルールとして足していってます
今あるルールの例

- PR は1つの依頼につき1つ
- マージは自分が指示したときだけ
- 「動いた」は、ログじゃなくて画面や届いたもので確かめてから言う
- プロセスを上限なしで並列起動しない
  742本立ち上げて Mac が固まったことがある。。
- 人が読む文字は少なく短く

#### スキル

よく使うやつ

- `dev`
  設計 → 実装 → レビュー → PR 作成までやるやつ
- `review_and_fix`
  レビュアーを回して指摘を直すやつ
- `pr-body`
  PR 本文の書き方
- `slack-post`
  Slack に投稿する文の書き方
- `ui-design`
  画面を作る前に案を出させるやつ
- `wait`
  レビューや CI を1時間ごとに確かめるやつ

#### サブエージェント

- Codex 系
  実装、コードレビュー、設計レビュー、要件の穴出し
- Claude 系
  コードレビュー、設計レビュー、読みやすさのレビュー、デザインシステムに沿ってるかのチェック

#### 権限とフック

- 権限は auto モード
  よく使うコマンドは許可リスト、消す系の操作は ask リストに入れてる
- フックは日本語で答えさせるやつだけ

### 開発の流れ

1. チャットで依頼する（Issue があれば URL を渡す）
2. `dev` スキルで設計・実装
3. レビュアーのサブエージェントを回して直す
4. PR の URL が返ってくる
5. 自分で見て「マージして」と指示する

### 小ネタ

- 数行の直しは Claude に自分で書かせる
  Codex に頼むと1件4〜6分かかってた
- テストとレビューは push の前に1回だけ回す
- 確認用の開発サーバーは `nohup` で切り離して起動させる
  アプリと一緒に落ちて、URL 開いたら死んでることがあったので
- Word や Excel は `open -g` で裏で開かせる
  作業中の画面の前にいきなり出てきて邪魔だったので
